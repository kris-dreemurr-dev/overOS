**overOS** — модульная 64-битная операционная система для x86_64, написанная с нуля на C99 и NASM. Ни в ядре, ни в модулях, ни в программах не используется libc и сторонние библиотеки.

Система загружается на реальном железе собственным двухстадийным загрузчиком из FAT32, работает в higher-half виртуальном пространстве, изолирует процессы аппаратно (Ring 3), вытесняюще их планирует, поддерживает USB 2.0 (EHCI/BOT/SCSI), многопользовательский режим с правами UNIX, шесть виртуальных терминалов с оболочкой в Ring 3 и графическую среду с композитором по протоколу в духе Wayland. В составе — встроенная IDE с компилятором Си, собирающая программы прямо внутри запущенной ОС, и порты DOOM и Quake.

## 1. Из чего состоит система

| Слой | Что это | Ring |
| :--- | :--- | :---: |
| `kernel.bin` | монолитное ядро: память, планировщик, сисколлы, TTY, VFS, драйверы | 0 |
| `.sys` (SREL, магия `DSYS`) | подгружаемые модули ядра, сервисы ядра — только через таблицу `devos_api_t` | 0 |
| `.prg` (DPRG) | прикладные программы в изолированном адресном пространстве, база `0x4000000000` | 3 |
| `/sys/login.prg`, `/sys/sh.prg` | getty/login и оболочка — обычные программы Ring 3 | 3 |
| `desktop.prg` | композитор и рабочий стол, окна живут вне ядра | 3 |
| `libui` (`src/libs/libui`) | набор виджетов и протокол окон для приложений | 3 |

Объём: ~40 тыс. строк собственного кода системы (ядро, драйверы, ФС, модули, библиотеки, программы) плюс порты игр.

## 2. Почему оно работает

1. **Higher-Half Kernel.** Ядро скомпоновано по `0xFFFFFFFF80000000`, младшая половина адресного пространства свободна под процессы. Верхняя половина PML4 зеркалируется в каждый процесс, поэтому вход в ядро не требует смены `CR3`.
2. **Аппаратное переключение стека (TSS).** При входе в Ring 0 процессор сам берёт стек из `TSS.RSP0`, который планировщик обновляет на каждом переключении задач. Сбойное приложение не может повредить стек ядра.
3. **Проверка указателей на границе.** `user_args_ok` в диспетчере сисколлов обходит таблицы страниц вызывающего (`vmm_user_range_ok`): каждая страница буфера должна быть present и USER на всех уровнях. Передать ядру адрес ядра невозможно.
4. **BIOS-to-OS Handoff для EHCI.** Система отбирает контроллер USB у прошивки через `USBLEGSUP` и протокол SMI, иначе DMA зависает при первом обращении к флешке.
5. **Когерентность кэша для DMA.** Работа с дескрипторами EHCI сопровождается `clflush` и `mfence`, контроллер читает актуальные структуры из ОЗУ.
6. **Изоляция сбоев.** Исключение в Ring 3 убивает процесс; исключение в Ring 0 даёт BSOD с дампом регистров. Решение принимается по CS в кадре исключения, а не по глобальному флагу, потому что ядро может держать `fs_lock` посреди сисколла.

## 3. Как оно работает

### 3.1. Пайплайн загрузки

```text
[ BIOS MBR (LBA 0) ]
        │
        ▼ Читает 32 сектора (16 КиБ) по адресу 0x1000 (INT 13h Ext)
[ Stage 2 ASM (boot_stage2.asm + boot_fat32.asm) ]
        │ • Fast A20 и Flat Unreal Mode (лимит ES = 4 ГБ)
        │ • MBR -> раздел FAT32 -> BPB
        │ • Поиск /sys/KERNEL.BIN по цепочке кластеров, загрузка в 0x100000
        ▼
[ Stage 2 C 16-bit (vbe_menu.c) ]
        │ • Опрос видеорежимов VBE 2.0+ (INT 10h AX=4F00h / 4F01h)
        │ • TUI-меню выбора разрешения
        │ • Установка режима LFB 32 bpp, ModeInfoBlock в 0x8000
        ▼
[ Protected Mode (32-bit) ] ──► jmp 0x100000
        │
        ▼
[ entry_kernel.asm ]
        │ • FPU (fninit), SSE/SSE2 (CR4.OSFXSR), PAE
        │ • 4-уровневый пейджинг (2 МБ huge pages: identity 0-4 ГБ + higher-half)
        │ • Long Mode в MSR EFER (LME), CR0.PG
        │ • GDT64, RSP = 0xFFFFFFFF81F00000, очистка .bss
        ▼
[ kernel_main() ]
        │ VBE-инфо -> pmm_init/vmm_init -> карта LFB (write-combining)
        │ -> tty_init_core() -> init_user_mode() (GDT/TSS/int 0x80)
        │ -> PIC remap + PIT 1000 Гц + sti -> калибровка TSC
        │ -> kernel_system_bootstrap() (USB, FAT32, подсветка, HDA, сеть)
        │ -> логотип -> sched_init() -> задача TTY1 -> бесконечный цикл init
        ▼
[ tty1: /etc -> /autostart/desktop.prg -> /sys/login.prg ]
```

Главный цикл `kernel_main` — это процесс init (pid 0): он обслуживает PS/2, мигает курсором и дважды в секунду собирает осиротевшие процессы (`sched_reap_orphans`).

### 3.2. Управление памятью

* **Объём ОЗУ берётся у BIOS.** Stage 2 ещё в реальном режиме запрашивает карту памяти (INT 15h, EAX=E820) и кладёт её по адресу `0x5800`; `kernel_main` отдаёт аллокатору только участки типа 1, а область ACPI и дыра PCI остаются занятыми. Потолок — 32 ГБ: столько адресует битовая карта в один мегабайт.
* **PMM (`pmm.c`):** битовая карта физических фреймов по 4 КиБ. Нулевая страница зарезервирована, чтобы аллокатор никогда не вернул адрес, равный `NULL`. Поиск идёт от подсказки и перешагивает занятые байты целиком — без этого выделение 50 МБ под процесс означало 12 800 проходов по всей карте, и именно отсюда брались паузы при открытии картинки или видео. Непрерывные куски (`pmm_alloc_pages`) выделяются строго ниже 4 ГБ: это буферы DMA, а контроллеры у нас 32-битные.
* **VMM (`vmm.c`):** трансляция `PML4 -> PDPT -> PD -> PT`. Вся физическая память отображена ядру прямым окном по адресу `0xFFFF8000'00000000` (страницы по 2 МБ, таблицы — в `.bss` ядра): без него ядро не могло адресовать страницу выше первого гигабайта. Образ ядра по-прежнему живёт по `0xFFFFFFFF80000000`. Для процесса создаётся свой PML4 (`vmm_create_address_space`): верх — ядро, прямое окно — общее, низ — процесс. `vmm_clone_address_space` побайтово клонирует пользовательские страницы для `fork`.
* **Куча процесса:** `sys_brk` и растёт, и **сжимается** — опускание границы снимает отображение (`vmm_unmap_page_take`) и возвращает страницы в PMM. Регрессионный тест: `heaptest.prg` прогоняет 400 × 4 МБ на машине с 1 ГБ.
* **Разделяемая память:** страницы с флагом `VMM_FLAG_SHARED` не копируются при `fork` и не освобождаются при разрушении адресного пространства; их отпускает `ipc_task_exit`, когда исчезло последнее отображение.

### 3.3. Планировщик и процессы

* Вытесняющий round-robin на тиках PIT (1000 Гц), квант 20 мс; переключение контекста — `switch.asm` (сохраняет `RBP`, `RBX`, `R12`–`R15`, меняет `RSP`, `CR3` — только при смене адресного пространства).
* У каждой задачи свой ядерный стек 64 КиБ, вершина заносится в `TSS.RSP0`.
* Состояние FPU/SSE сохраняется при переключении (`fxsave`/`fxrstor` в `switch_to`): до этого регистры xmm были общими на всю систему и задачи портили их друг другу. Регрессионный тест — `fputest.prg`.
* **POSIX-примитивы:** `fork` (30) клонирует дерево страниц, ядерный стек и кадр прерывания с обнулением RAX у потомка; `execve` (31) уничтожает старое пространство, загружает образ и подменяет RIP/RSP прямо в сохранённом кадре; `waitpid` (32) и `kill` (33) с зомби и сигналами `SIGINT`/`SIGKILL`; `getpid` (110); `spawn` (109) запускает программу без `fork`, чтобы композитор не копировал свои многомегабайтные буферы ради `execve`.
* **Сироты уходят к init:** `reparent_children` передаёт детей умирающей задачи процессу pid 0. Тест — `orphan.prg` + `ps`.
* `sched_sleep_ms` и `ipc_recv` переводят задачу в `TASK_SLEEPING`, простой использует `hlt`: ждущее приложение не тратит процессор.

### 3.4. Пользователи и права (UNIX DAC)

* У задачи есть `uid`/`gid`, они наследуются при `spawn` и `fork`; потоки ядра — root.
* `/etc/passwd`, `/etc/group`, `/etc/shadow`, `/etc/perms` читаются в `tty1_task_entry` до автостарта. Хэш пароля — `$ov$salt$sha256(salt+pass)`. Каждый файл `/etc` пишется вместе с резервной копией `<file>-` и читается из неё, если основной потерян.
* FAT32 не хранит владельцев, поэтому права живут в `/etc/perms`: `путь uid gid восьмеричный-режим`. Путь без своей строки наследует ближайшего предка. `perm_check` требует X на всех родительских каталогах; root проверку обходит.
* Проверки стоят в `vfs_sys_open`, сисколлах 16/17/18/31/33, при загрузке модуля (X) и во встроенных командах. Сырая клавиатура и мышь (6/7/23/24) и `/dev/fb0` доступны только процессу переднего плана своего TTY — фоновый процесс не подсмотрит пароль следующего пользователя.
* **Админская модель как в десктопном Linux:** члены группы `wheel` поднимают права **своим** паролем — `sudo <команда>`, `sudo -i`, сисколл 93. Root после первоначальной настройки заблокирован (`!` в shadow), как в Ubuntu.
* **Первоначальная настройка (OOBE)** запускается, если `/etc/oobe` не `1` и нет пользователя с uid ≥ 1000: язык, часовой пояс, вторая раскладка, администратор. В консоли мастер показывает `login.prg`, в графике — `greeter.c`.
* Системные настройки: `/etc/locale.conf` (`LANG`), `/etc/timezone` (имя зоны, смещения в таблице `g_timezones`), `/etc/vconsole.conf` (`XKBLAYOUT=us` или `us,ru` — он же разрешает переключение раскладки). Настройки рабочего стола — свои у каждого пользователя (`~/.config/desktop.json`).

### 3.5. Терминалы, вход и оболочка в Ring 3

* Шесть виртуальных терминалов, `Alt+F1`..`Alt+F6`; TTY 2..6 выделяются лениво.
* **Консоль принадлежит TTY, а не системе:** курсор, прокрутка назад, строка ввода, цвет фона и текущий каталог — поля `tty_t`, а `tty_console()` возвращает TTY **вызывающей задачи**. Оболочка в фоновом терминале пишет в свой буфер, `flush_buffer` трогает видеопамять только для активного TTY.
* **Канонический ввод в ядре** (`tty_line_read`): эхо, Backspace, раскладка и Shift — работа драйвера, программа просто читает строку из `/dev/tty`. `ioctl(0, OV_TTY_ECHO, 0)` гасит эхо для пароля — аналог termios.
* **Caps Lock** ведётся в `ps2_hw_service` (скан-код `0x3A`) и зажигает светодиод клавиатуры (команда `0xED`). Регистр он меняет **только у букв** — цифры и знаки не трогает. Композитор держит своё состояние `g_caps_on`: в трее появляется значок замка (список окон ужимается на его ширину, как в KDE), а окно входа пишет «Caps Lock включен» рядом с полем пароля.
* **В терминале одна раскладка — английская**, как в консоли Linux: переключение по Alt и таблица CP866 из драйвера убраны. Русский набирается в графическом сеансе, где раскладку применяет композитор. Имена файлов везде UTF-8, консоль переводит их в CP866 только при выводе.
* Переключение терминала «съедало» отпускание модификаторов: Alt нажимали в одном TTY, а код `0xB8` уходил уже в другой, и рабочий стол считал Alt зажатым — после `Alt+F2` → `Alt+F1` окна переставали получать набранный текст. `tty_switch` теперь сбрасывает модификаторы и досылает коды отпускания в новый терминал.
* **Процесс переднего плана.** Читать TTY может только он. Оболочка отдаёт клавиатуру потомку через `sys_tty_setfg` (112, аналог `tcsetpgrp`) и забирает обратно после выхода, перерисовывая консоль.
* `tty_shell_loop` в ядре — теперь только getty: печатает шапку терминала и запускает `/sys/login.prg`, перезапуская его при падении. Встроенная оболочка ядра осталась как резерв, её сервисные команды доступны из Ring 3 через мост `sys_kcmd` (118).
* `/sys/login.prg` работает от root (как getty): первоначальная настройка, приглашение входа, `sys_auth`, затем запуск оболочки **с uid/gid пользователя**.
* `/sys/sh.prg` — оболочка: `ls`, `cd`, `pwd`, `cat`, `mkdir`, `touch`, `echo текст > файл`, `whoami`, `id`, `su`, `sudo`, `passwd`, `useradd`, `chmod`, `chown`, `stat`, `ps`, запуск `.prg`. `su` меняет права **в потомке**: процесс не может повысить себя обратно, поэтому оболочка, вызвавшая `sys_su` на себе, навсегда осталась бы другим пользователем.
* `Ctrl+C` уходит процессу переднего плана активного TTY, но игра, гоняющая кадры, получает Ctrl и C как обычные клавиши. `Ctrl+Alt+C` убивает её всегда — аналог `Ctrl+Alt+Backspace` в X; композитор от этого защищён и имеет свой выход из сеанса.

### 3.6. Файловые системы и устройства

* **FAT32 (`fat32.c`):** длинные имена (цепочки записей `0x0F`, декодирование UTF-16) с проверкой контрольной суммы LFN против записи 8.3, регистр NTRes, объединение смежных кластеров в один пакетный USB-запрос, синхронизация спинлоком `fs_lock` с уступкой кванта.
* **Позиция каталога — параметр операции, а не состояние системы:** `fs.c` перед каждым вызовом заводит драйвер в `fs_caller_cwd()` (поле `task_t.cwd` процесса) и кэширует, где драйвер стоит. Поэтому `cd` в одном TTY не ломает путь в другом.
* **VFS (`vfs.c`):** до 32 дескрипторов, `read` учитывает смещение (`fat32_read_at`, неполные секторы через bounce-буфер), `write` в нулевое смещение заменяет файл целиком, запись дальше делает read-modify-write до 16 МБ.
* **devfs:** `/dev/tty` (строчный ввод и `ioctl` эха), `/dev/fb0` (кадровый буфер), `/dev/null`, `/dev/zero`, `/dev/memory`.
* **USB — слоями:** `drivers/usb/usb.c` (какие контроллеры поднимать, опрос портов, замок шины) → `ehci.c` + `ehci-msc.c` (USB 2.0: очереди QH/qTD, встроенный хаб Intel RMH) и `xhci.c` + `xhci-msc.c` (USB 3.0: кольца TRB, слоты, контексты) → `drivers/blk.c` (реестр дисков: номер диска → его драйвер). Драйверы контроллеров друг о друге не знают, о файловой системе — тоже. Транспорт MSC/BOT: CBW 31 байт, Bulk IN/OUT, CSW 13 байт; SCSI `INQUIRY`, `TEST UNIT READY`, `READ CAPACITY`, `READ (10)`, `WRITE (10)`.
* **Несколько накопителей и горячее подключение (`fs/mount.c`, поток `storaged`):** корень — FAT32, на котором лежит `/sys/KERNEL.BIN`; остальные флешки подключаются сами в `/media/<метка>` (MBR, GPT или носитель без таблицы разделов), «Извлечь» снимает их безопасно, а выдернутая флешка с системой узнаётся по VID:PID, размеру и серийному номеру тома и перемонтируется. FAT32 держит таблицу томов, `fs.c` отправляет путь внутри `/media/<имя>` на свой том.
* Прочие драйверы: PCI, ACPI, PS/2 клавиатура и мышь, подсветка панели, Intel HDA (вывод PCM, громкость, выбор выхода, определение джека), Ethernet RTL8168 с ARP/IPv4/UDP/ICMP/DHCP и командами `ping`/`pingd`.

### 3.7. Графика, композитор и рабочий стол

* VBE LFB, 32-битный TrueColor, отображён с write-combining. Рендеринг идёт во внеэкранный буфер, вывод — `rep movsq`.
* **Грязные прямоугольники:** `mark_dirty`/`flush_dirty` отправляют на экран только изменившуюся область, поэтому печать одного символа не гонит весь кадр.
* У каждого TTY своя история прокрутки назад (64 строки), индексируемая шагом `screen_width`.
* **Ядро ничего не знает об окнах.** `desktop.prg` — композитор: он регистрирует IPC-имя `desktop`, клиенты находят его через `ov_lookup`.
* **Протокол окон (`src/libs/common/wproto.h`), по духу Wayland:** клиент создаёт shm-буфер `w*h*4`, выдаёт его композитору и присылает `WP_CREATE`; рисует в этот буфер и присылает `WP_COMMIT`; следующий кадр начинает после `WP_FRAME_DONE`. Композитор собирает кадр прямо из буфера клиента — без копирования через ядро.
* События клиенту: `WP_EV_MOUSE`, `WP_EV_KEY` (скан-код, модификаторы **и** готовый UTF-8 — раскладку применяет композитор), `WP_EV_SCROLL`, `WP_EV_FOCUS`, `WP_EV_CLOSE` (клиент выходит сам, через 2 с его убивает `wserver_tick`), `WP_EV_COMMAND` (пункты контекстного меню).
* **Экран входа** в духе KDE Plasma: список пользователей с аватарами из `/etc/passwd`, выбор стрелками или мышью, вводится только пароль, список обновляется каждые ~2 с. Рабочий стол работает от root, как дисплей-менеджер, и запускает приложения сеанса под uid/gid пользователя.
* **Панель задач:** часы по `/etc/timezone` со списком поясов, громкость, яркость, обои, выход из сеанса.
* **Тулкит:** `ui_open`/`ui_begin`/`ui_end` оборачивают кадр, виджеты immediate-mode (`ui_button`, `ui_slider`, `ui_textbox`, `ui_password`, `ui_list`, `ui_checkbox`, `ui_label`, `ui_progress`), тема общая, шрифт CP866 8x16 с вводом UTF-8. `ui_begin(w, UI_WAIT)` блокируется до события, поэтому простаивающее приложение не ест процессор. Makefile приложения — четыре строки плюс `include ../../../lib/app.mk`.
* **Библиотеки системы (`/lib/*.ll`):** `libc.ll` и `libm.ll` — язык и математика; **`ffmpeg.ll`** — настоящий FFmpeg, собранный под overOS, за простым набором вызовов `av_open`/`av_audio_read`/`av_video_decode_until`/`av_video_blit`; `libgfx.ll` — картинки (PNG, BMP), шрифты и значки; `libui.ll` — тулкит окон. Плеер после переезда декодеров в `ffmpeg.ll` занимает 9 КБ кода вместо 20 КБ и 64 КБ памяти вместо 43 МБ.
* **libui (`src/libs/libui`):** приложения не трогают протокол и не рисуют виджеты руками.
* Приложения: overFiles (файловый менеджер), notepad, overImages (BMP и PNG), overPlayer (звук и видео через ffmpeg.ll), **Терминал**, **Диспетчер задач** и **Параметры системы**. Как написать своё — `src/files/progs/readme.md`.
* **Терминал** разбирает команды сам, а не запускает `/sys/sh.prg`: каналов (pipe) и псевдотерминалов в ядре ещё нет, перехватить вывод чужой программы нечем. Встроенные команды он делает системными вызовами, а внешние программы запускает в текстовую консоль и честно об этом пишет.
* **Курсор меняет форму:** стрелка, двутавр над текстовым полем, часы на долгой работе, перетаскивание и четыре стрелки изменения размера. Края окна подставляет композитор, внутри окна форму просит программа (`WP_CURSOR`, `ui_cursor`).

#### Внешний вид

* **Шрифт интерфейса — настоящий .ttf, разбирается в системе.** `src/libs/libgfx/ttf.c` читает таблицы cmap/loca/glyf/hmtx, переводит контуры в многоугольники и закрашивает их со сглаживанием (супервыборка 4x4), готовые глифы складывает в кэш. Файл лежит в `/sys/fonts/ui.ttf` — положите другой, и интерфейс нарисуется им (`make UI_FONT_TTF=...` кладёт в образ ваш). Если файла нет, рисуем прежним растровым 8x16, как в консоли. В редакторе и консоли моноширинный шрифт остаётся всегда.
* **Значки — .svg из `/sys/icons`**, их растеризует `src/libs/libgfx/svg.c` (пути, фигуры, обводки, прозрачность, преобразования; покрытие по горизонтали считается точно, по вертикали 16 подстрок). `fill="currentColor"` означает «цветом, который попросит интерфейс», поэтому один файл годится и для обычного состояния, и для подсветки.
* **Окна в духе Breeze:** скругление со всех сторон (в развёрнутом виде углы прямые), тёмная шапка с заголовком по центру, кнопки «свернуть / развернуть / закрыть».
* **Размер окна меняется мышью:** за край тянется контур, а настоящий размер применяется по отпусканию — буфер кадра принадлежит клиенту, и пересоздавать его на каждое движение мыши дорого. Разворачивание и перетаскивание края идут через одно и то же событие протокола (`WP_EV_RESIZE` → `WP_RESIZE`).
* **Панель задач — док значков:** кнопка меню приложений (только значок), закреплённые программы (`"pinned"` в `desktop.json`) и запущенные окна; ПКМ по значку — «Закрепить/Открепить» и «Закрыть окно».

* overFiles умеет «Доступ запрещён → Разблокировать» (`sys_sudo` по своему паролю, как в Dolphin). В режиме администратора он запускает программы **со своими правами**: иначе блокнот, открытый из разблокированной папки, тут же писал «Нет доступа к файлу».
* **Форматы.** Звук и видео целиком на `/lib/ffmpeg.ll` — это настоящий FFmpeg, собранный под overOS (раздел 3.9.1): MP4/MOV, MKV, AVI, MP3, WAV, видео H.264, звук AAC вместе с HE-AAC. Плеер сам не декодирует ничего: он открывает файл, забирает готовый PCM и готовые кадры по времени показа. Наши собственные декодеры MP3, MP4, H.264 и AAC, которые раньше жили в `src/lib`, после порта удалены — всё, что они умели, FFmpeg умеет лучше (они остались в истории git).
* PNG читает свой декодер `src/libs/libgfx/png.h`: собственная распаковка DEFLATE, все пять фильтров строк, типы цвета 0/2/3/4/6, глубина от 1 до 16 бит, прозрачность палитры. Вся арифметика целочисленная.

### 3.8. IPC и разделяемая память

* `src/kernel/ipc.c`: почтовый ящик на процесс (`ipc_msg_t`, до 256 байт), имена сервисов, разделяемая память. Ядро само ставит в сообщение pid и uid отправителя — подделать нельзя.
* `ipc_recv` блокируется в планировщике, поэтому ждущий сервис не крутит цикл.
* Сегменты лежат от `SHM_BASE` (`0x5000_0000_0000`), по слоту 64 МБ на id, поэтому один и тот же объект имеет один и тот же адрес во всех процессах.

### 3.9. Разделяемые библиотеки `.ll`

`.ll` (linked library) — это для overOS то же, чем `.so` для Linux и `.dll` для Windows: кусок кода, который не вкомпилирован в программу, а подключается во время работы.

* Собирается `tools/elf2ll.py` из перемещаемого ELF (PIE, база 0, `--emit-relocs`) и несёт образ, таблицу релокаций и таблицу экспорта «имя -> смещение».
* Ядро (`src/kernel/lib_loader.c`) кладёт библиотеку в адресное пространство **того процесса, который её открыл**: `LIB_BASE` = `0x6000_0000_0000`, по слоту 64 МБ, до 16 библиотек на процесс. После копирования образа ядро прибавляет базу к ячейкам из таблицы релокаций — поэтому библиотеке всё равно, по какому адресу её положили.
* Связывания на этапе компоновки нет: программа берёт адрес символа по имени и вызывает его как обычную функцию. Это модель `dlopen`/`dlsym`, а не динамического линковщика.
* Импорта у библиотеки нет вообще: всё, что ей нужно от системы, она делает сама через `int 0x80`. Упаковщик отказывается собирать библиотеку, в которой остался хоть один неразрешённый символ.
* `fork` отдаёт ребёнку те же образы (память копируется вместе со всем адресным пространством), `execve` и завершение процесса освобождают слоты.

Исходники всех библиотек лежат в `src/libs`, каждая в своём каталоге: рядом с исходником библиотеки — её заголовок подключения `<имя>_ll.h`, который включает в себя программа. Подробный разбор формата, раскладки каталога и порядка добавления своей библиотеки — в **`src/libs/readme.md`**.

В образе лежат пять:

| Файл | Что внутри |
| :--- | :--- |
| `/lib/libc.ll` | `mem*`, `str*`, `is*`/`to*`, `atoi`/`strtol`/`itoa`, `malloc`/`free`/`calloc`/`realloc` (куча на `brk`), `qsort`/`bsearch`, `rand`, `snprintf`/`printf` |
| `/lib/libm.ll` | `sqrt`, `exp`, `log`, `log2`, `log10`, `pow`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `expm1`, `log1p`, `floor`, `ceil`, `round`, `fmod`, `hypot`, `ldexp`, `frexp` + версии для `float` |
| `/lib/ffmpeg.ll` | **настоящий FFmpeg** (libavformat, libavcodec, libswscale, libswresample) за простым набором вызовов `av_*` |
| `/lib/libgfx.ll` | картинки (PNG, BMP), растеризатор шрифтов `.ttf` и значков `.svg` |
| `/lib/libui.ll` | весь тулкит окон: окна, виджеты, шрифт, ввод |

Приложения рабочего стола уже переведены на общие библиотеки: в makefile стоит `USE_LIBUI := 1`, в коде — `#include "libui/libui_ll.h"` и вызов `libui_bind()` в начале `main`. Имена функций подменяются макросами на поля таблицы указателей, поэтому сам код приложений не менялся. Размеры после перехода:

| Программа | Было | Стало |
| :--- | ---: | ---: |
| `ovplayer.prg` | 146 КБ | 9 КБ |
| `ovfiles.prg` | 37 КБ | 21 КБ |
| `ovimage.prg` | 34 КБ | 9 КБ |
| `notepad.prg` | 25 КБ | 9 КБ |

Это та самая libc, которой в системе нет на этапе компоновки: ядро, модули и программы как собирались freestanding, так и собираются, а libc подключается в runtime и только тем, кому она нужна. Точность libm проверена против glibc: максимальное относительное отклонение ~2e-15 на всех функциях.

### 3.9.1. `/lib/ffmpeg.ll` — настоящий FFmpeg

`ffmpeg.ll` — это не обёртка над своими декодерами, а **собранный под overOS FFmpeg 7.1**: libavformat, libavcodec, libswscale и libswresample целиком.

Чтобы он собрался, системе понадобился «сисрут» — то, чего в overOS никогда не было:

* `src/libs/ffmpeg/include` — заголовки (`stdio.h`, `stdlib.h`, `string.h`, `math.h`, `time.h`, `errno.h`, `unistd.h`, `fcntl.h`, `sys/*`), описывающие ровно то, что система умеет;
* `src/libs/ffmpeg/ffsys.c` — их реализация: куча, `strtod`, `sscanf`, файловый ввод-вывод прямо на сисколлах, время, недостающая математика. Рядом в ту же библиотеку линкуются наши `libc/libc.c` и `libm/libm.c`;
* `src/libs/ffmpeg/ovcc` — обёртка над gcc: `-ffreestanding -nostdinc` с этим сисрутом и своя библиотека при компоновке. Благодаря ей `./configure` проверяет функции честно и находит только те, что у нас есть, а всё остальное FFmpeg подставляет своим кодом;
* `tools/build_ffmpeg.sh` — распаковка, заплаты, конфигурация, сборка и упаковка в `.ll` одной командой. Запускается из `make`.

Куча у FFmpeg своя — пул на 64 МБ внутри библиотеки, а не `brk`: границу кучи процесса уже двигает `libc.ll`, и два распределителя на одной границе затёрли бы друг друга. Файл читается своим `AVIOContext` прямо через дескриптор ядра, целиком в память он больше не загружается — ради этого в ядре появился настоящий `lseek` (сисколл 19).

Что из этого вышло: **HE-AAC (SBR и параметрическое стерео) играет полностью**, а не одним ядром AAC-LC в 22 кГц; открываются MKV и AVI; картинка масштабируется libswscale со сглаживанием вместо ближайшего соседа. Что осталось нашим: окно, вывод звука и лимитер (`src/libs/ffmpeg/limiter.h`) — FFmpeg, как и раньше, выдаёт материал громче полной шкалы.

Наши собственные декодеры MP3, MP4, H.264 и AAC после этого удалены из дерева: FFmpeg делает всё то же и больше, а два набора кодеков в системе — это два места, где искать ошибку. Если понадобятся, они есть в истории git.

Как это выглядит в программе:

```c
#include "ovos.h"
#include "libm/libm_ll.h"       // готовая привязка (src/libs/libm)

libm_t m;
if (libm_load(&m) == 0) {
    double y = m.sin(x) * m.exp(-x);
    libm_unload(&m);
}

// или вручную, как dlopen/dlsym:
int h = ov_lib_open("/lib/libm.ll");
double (*sq)(double);
OV_BIND(h, sq, "sqrt");
```

Регрессия — `/programs/lltest.prg`: гоняет кучу, строки, сортировку и сверяет два десятка математических функций с эталонами, посчитанными на хосте.

## 5. Встроенная IDE и компилятор (`redactor.sys`)

Текстовый редактор и однопроходный компилятор Си, работающие как модуль Ring 0:

* **Интерфейс:** многовкладочный TUI в тёмной теме с подсветкой синтаксиса Си.
* **Препроцессор:** `#include` (из соседних вкладок или `/Code/`) и `#define`.
* **Кодогенератор:** рекурсивный спуск, машинный код x86_64, стековые кадры по System V ABI, локальные переменные.
* **Три цели сборки:**
  1. `F5` — JIT: компиляция в буфер ОЗУ и запуск под защитой `g_jit_guard` (Ring 0).
  2. `F8` — приложение `.PRG`: вызовы транслируются в `int 0x80`, пул строк, база `0x4000000000` (Ring 3).
  3. `F9` — модуль `.SYS`: перемещаемый драйвер с таблицей релокаций SREL (Ring 0).

Остальные модули: `mc.sys` (файловый менеджер), `memedit.sys` (редактор памяти), `cpu.sys` (CPUID/MSR), `hwinfo.sys` (SMBIOS, GPU, ОЗУ), `gpu.sys`, `stress.sys` (стресс-тест с пробуждением остальных ядер через SIPI), `cloak.sys` (RTC-часы).

## 7. Сборка и запуск

### 7.1. Зависимости

```bash
# Arch Linux / CachyOS
sudo pacman -S base-devel gcc nasm mtools dosfstools qemu-system-x86 python

# Ubuntu / Debian
sudo apt install build-essential gcc nasm mtools dosfstools qemu-system-x86 python3
```

### 7.2. Основные цели

```bash
make                  # полный образ build/os.img (MBR + stage2 + раздел FAT32)
make run              # сборка и запуск в QEMU (KVM, USB EHCI, intel-hda, serial на stdio)
make run-debug        # то же под TCG с трассировкой прерываний в qemu_error.log
make modules          # только .sys
make libs             # только разделяемые библиотеки .ll
make progs            # только .prg
make compile-commands # compile_commands.json для clangd / VS Code
```

Параметры образа: `PART_SIZE_MB`, `INSTALL_MODULES`, `INSTALL_PROGS`, `WITH_DOOM`, `WITH_QUAKE`, `WITH_DESKTOP`, учётные записи `ROOT_PASS` / `OS_USER` / `OS_PASS`. По умолчанию `OS_USER` пуст: в образе только root, `/etc/oobe` равен `0`, и при первом запуске открывается первоначальная настройка. `make OS_USER=kris OS_PASS=...` создаёт администратора сразу и пропускает мастер. Пустой `ROOT_PASS` блокирует root, как в Ubuntu.

### 7.3. Запись на флешку

```bash
make install                       # интерактивный установщик (sudo, пишет на реальный диск)
make install-modules DEV=/dev/sdX  # обновить файлы на уже записанной флешке
```

После записи подключите флешку и выберите её в меню загрузки BIOS (Legacy / CSM).

## 8. Состояние и планы

Сделано: вытесняющая многозадачность, изоляция Ring 3, многопользовательский режим с правами UNIX, оболочка и вход в Ring 3, канонический ввод TTY, шесть терминалов, FAT32 с LFN на USB, IPC и разделяемая память, композитор с протоколом окон, набор приложений, встроенный компилятор, разделяемые библиотеки `.ll` с libc и libm.

В работе и на будущее:
* сервисные команды ядра (`taskmgr`, `ping`, `playsound`, `fastfetch`) всё ещё живут в `main.c` и доступны через мост `sys_kcmd` — их место в отдельных `.prg`;
* точки монтирования есть только в `/media` (флешки) и только для FAT32: exFAT и NTFS пока узнаются, но не читаются; `/dev` — по-прежнему особый случай;
* нет каналов (`pipe`), перенаправления ввода и обработчиков сигналов: `kill` умеет только убить или прервать;
* носители — только USB MSC, ФС — только FAT32: нет AHCI/NVMe и ФС с владельцами и правами в самих метаданных;
* ELF как формат исполняемых файлов не поддержан (свои DPRG/SREL/DLIB);
* SMP: остальные ядра пока только просыпаются для стресс-теста (`src/modules/asm/smp_trampoline.asm` ждёт полноценного подъёма в long mode);
* сеть на уровне ARP/IPv4/UDP/ICMP/DHCP, TCP и сокетов нет;
* картинки (BMP, PNG) читают свои разборщики, а звук и видео — настоящий FFmpeg в `/lib/ffmpeg.ll` (MP4/MOV, MKV, AVI, MP3, WAV, H.264, AAC и HE-AAC); собран он без ассемблерных вставок и без потоков, поэтому 4K ему не по силам;
* длинные имена файлов читаются и пишутся в UTF-8 (на диске UTF-16), ввод в терминале переключается Alt — русские имена работают и в консоли, и в проводнике.
