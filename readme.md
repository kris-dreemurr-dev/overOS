**overOS** — модульная 64-битная операционная система для архитектуры x86_64, написанная с нуля на Си и ассемблере NASM без использования сторонних библиотек и libc.

Система загружается на реальном оборудовании через собственный двухстадийный загрузчик из файловой системы FAT32, функционирует в Higher-Half виртуальном пространстве, поддерживает аппаратную изоляцию процессов (Ring 3), вытесняющую многозадачность, аппаратный стек USB 2.0 (EHCI/SCSI), виртуальные терминалы (мульти-TTY) и включает встроенную среду разработки с Си-компилятором, способную собирать прикладные программы прямо внутри запущенной ОС.

---

## 1. Что это такое?

* **Архитектура:** x86_64 (чистый 64-битный Long Mode).
* **Модель ядра:** Монолитное ядро с динамически подгружаемыми драйверами нулевого кольца защиты (`.SYS` формата SREL).
* **Пространство пользователя:** Полная аппаратная изоляция памяти и привилегий (Ring 3) для прикладных программ (`.PRG` формата DPRG).
* **Файловая система:** Собственные реализации FAT16 и FAT32 с длинными именами файлов (LFN), регистром NTRes и пакетным чтением.
* **Ввод-вывод:** Собственный стек USB EHCI для флеш-накопителей, драйвер контроллера прерываний (PIC), таймера (PIT), шины PCI, ACPI, PS/2 клавиатуры и мыши.
* **Графика и TUI:** Линейный 32-битный фреймбуфер VESA VBE с двойной буферизацией, растровый шрифт CP866 и мультиплексирование виртуальных консолей (Alt+F1 / Alt+F2).
* **Автономия:** Встроенная IDE `redactor.sys` с Си-компилятором (JIT/PRG/SYS), порты игр (DOOM, Quake), графопостроитель функций `math.prg`, графические демки и системный диагностический инструментарий.

## 2. Почему оно работает?

1. **Higher-Half Kernel Mapping:** Ядро скомпоновано по виртуальным адресам `0xFFFFFFFF80000000` (верхние 2 ГБ 64-битного адресного пространства). Это освобождает младшие адреса (`0x0000000000000000`–`0x00007FFFFFFFFFFF`) под изолированные адресные пространства процессов.
2. **Аппаратное переключение стека ядра (TSS):** При переходе процессора из Ring 3 в Ring 0 (по системному вызову `int 0x80` или аппаратному таймеру) процессор аппаратно загружает безопасный указатель стека из дескриптора состояния задачи (`TSS.RSP0`), исключая повреждение стека ядра сбойными приложениями.
3. **BIOS-to-OS Handoff для EHCI:** Система самостоятельно отбирает аппаратное управление контроллером USB 2.0 у прошивки материнской платы через регистр `USBLEGSUP` и протокол SMI, предотвращая блокировку DMA-контроллера при обращении к флешке.
4. **Когерентность процессорного кэша:** Взаимодействие с DMA-структурами USB сопровождается принудительным сбросом кэш-линий процессора инструкциями `clflush` и барьерами `mfence`, благодаря чему контроллеры читают актуальные дескрипторы прямо из ОЗУ.
5. **Безопасная обработка исключений CPU:** Сбои прикладных программ (деление на ноль, GPF, Page Fault) изолируются: ядро не падает в панику, а корректно завершает сбойный процесс и возвращает управление в шелл.

## 3. Как оно работает?

### 3.1. Пайплайн загрузки системы (Boot Sequence)

```text
[ BIOS MBR (LBA 0) ]
        │
        ▼ Читает 32 сектора (16 КиБ) по адресу 0x1000 (INT 13h Ext)
[ Stage 2 ASM (boot_stage2.asm + boot_fat32.asm) ]
        │ • Включение Fast A20 и Flat Unreal Mode (лимит ES = 4 ГБ)
        │ • Парсинг MBR -> Раздел FAT32 -> BPB
        │ • Поиск файла /sys/KERNEL.BIN по кластерам и загрузка в 0x100000
        ▼
[ Stage 2 C 16-bit (vbe_menu.c) ]
        │ • Опрос видеорежимов через VBE 2.0+ (INT 10h AX=4F00h / 4F01h)
        │ • Интерактивное TUI-меню выбора разрешения (1024x768, Hardware Limit)
        │ • Установка режима LFB (32 bpp), сохранение ModeInfoBlock в 0x8000
        ▼
[ Переход в Protected Mode (32-bit) ] ──► jmp 0x100000
        │
        ▼
[ Инициализация x86_64 (entry_kernel.asm) ]
        │ • Включение FPU (fninit), SSE/SSE2 (CR4.OSFXSR), PAE[cite: 14]
        │ • Построение 4-уровневого пейджинга (2 МБ Huge Pages, Identity 0-4 ГБ + Higher-Half)[cite: 14]
        │ • Активация Long Mode в MSR EFER (LME) и включение CR0.PG[cite: 14]
        │ • Загрузка GDT64, установка RSP = 0xFFFFFFFF81F00000, очистка .bss[cite: 14]
        ▼
[ kernel_main() ] Точка входа основного ядра[cite: 14, 28]
```

### 3.2. Управление памятью (PMM и VMM)

* **Physical Memory Manager (`pmm.c`):**
  * Аллокатор на основе битовой карты по адресу `0xFFFFFFFF81F00000` (физически 31 МБ)[cite: 42].
  * Управляет физическими фреймами по 4096 байт[cite: 42, 43]. 1 бит = 1 страница[cite: 42]. При размере карты в 1 МБ адресуется до 32 ГБ ОЗУ[cite: 42].
  * Нулевая страница физической памяти (`0x00000000`) жестко зарезервирована, исключая выдачу адреса, эквивалентного `NULL`[cite: 42].
  * Поддерживает непрерывную аллокацию фреймов (`pmm_alloc_pages`) для DMA-буферов контроллеров[cite: 42].
* **Virtual Memory Manager (`vmm.c`):**
  * 4-уровневая трансляция: `PML4 -> PDPT -> PD -> PT -> Физическая страница`[cite: 44].
  * Первые 512 МБ физической памяти проецируются страницами по 2 МБ (Huge Pages, `0x80`) для снижения промахов TLB[cite: 44].
  * Для процессов создаются изолированные каталоги страниц `PML4`: верхняя половина зеркалирует ядро, нижняя отводится под процесс (`PROG_LOAD_BASE = 0x4000000000`)[cite: 33, 44].
  * Реализовано глубокое побайтовое клонирование пользовательских страниц памяти (`vmm_clone_address_space`) для системного вызова `fork()`[cite: 44].

### 3.3. Планировщик и модель процессов

* **Архитектура планировщика (`sched.c`):**
  * Вытесняющий Round-Robin планировщик на основе тиков PIT (1000 Гц) с квантом времени 20 мс[cite: 28, 34].
  * Ассемблерное переключение контекста (`switch_to`): сохраняет и восстанавливает регистры `RBP`, `RBX`, `R12`–`R15`, меняет `RSP`, а также обновляет `CR3` только при смене адресного пространства[cite: 8].
  * Каждая задача имеет собственный 64-КиБ ядерный стек (`PROC_KSTACK_SIZE`), а вершина стека при переключении потока заносится в `TSS.RSP0`[cite: 34, 35].
* **Примитивы процессов POSIX:**
  * `sys_fork` (сисколл 30): клонирует дерево страниц памяти, ядерный стек и копирует 160-байтный кадр прерывания родителя с обнулением слота RAX у потомка[cite: 40].
  * `sys_execve` (сисколл 31): уничтожает старое адресное пространство, загружает бинарник, перенастраивает стек на `0x00007FFFFFFF0000ULL` и подменяет регистры RIP/RSP прямо в сохраненном кадре прерывания[cite: 32, 40].
  * `sys_waitpid` (сисколл 32) & `sys_kill` (сисколл 33): обработка состояний зомби, доставка сигналов `SIGINT` (Ctrl+C) и `SIGKILL`[cite: 35, 40].
  * `sys_brk` (сисколл 14): динамическое расширение кучи пользовательского процесса с постраничным маппированием[cite: 40].

### 3.4. Аппаратный стек USB 2.0 (EHCI) и FAT32

* **Контроллер EHCI (`ehci.c`):**
  * Обнаруживает хост-контроллер на шине PCI (класс `0x0C`, подкласс `0x03`, ProgIF `0x20`), включает Bus Mastering[cite: 74, 77].
  * Реализует аппаратное взаимодействие через 64-байтные очереди Queue Head (QH) и 32-байтные дескрипторы qTD[cite: 77, 78].
  * Опрашивает внутренний хаб Intel Rate Matching Hub (RMH, класс `0x09`), запитывает и сбрасывает downstream-порты для подключения внешних флешек[cite: 77].
* **Блочный транспорт MSC / BOT (`ehci-msc.c`):**
  * Стандарт USB Mass Storage Bulk-Only Transport: упаковка команд в 31-байтные блоки CBW (`Command Block Wrapper`), обмен данными через Bulk IN / Bulk OUT и прием 13-байтного статуса CSW (`Command Status Wrapper`)[cite: 79, 80].
  * Программный контроль четности пакетов (Data Toggle) конечных точек[cite: 79].
  * SCSI-транслятор: `INQUIRY` (`0x12`), `READ CAPACITY` (`0x25`), `READ (10)` (`0x28`), `WRITE (10)` (`0x2A`)[cite: 79].
* **Файловая система FAT32 (`fat32.c`):**
  * Поддержка LFN (Long File Names, цепочки дескрипторов `0x0F` с декодированием UTF-16)[cite: 21].
  * Поддержка регистра имен NTRes (смешанный регистр 8.3 без генерации лишних LFN-записей)[cite: 21].
  * Run-Length Packet Reading: объединение смежных кластеров диска в непрерывные блоки для вычитывания за один пакетный USB-запрос[cite: 21].
  * Синхронизация потоков через атомарный спинлок `fs_lock` с уступкой кванта времени `sched_yield`[cite: 23].

### 3.5. Графический стек и мульти-TTY

* Линейный буфер кадра VBE LFB в 32-битном цвете (TrueColor)[cite: 16, 28].
* Двойная буферизация: рендеринг ведется во внеэкранном массиве `back_buffer`, сброс на экран оптимизирован через инструкцию `rep movsq`[cite: 28].
* Мультиплексирование консолей: `TTY 1` и `TTY 2` с переключением по `Alt+F1` и `Alt+F2`[cite: 29, 39]. Буфер TTY 2 выделяется лениво из страниц PMM при первом вызове[cite: 38]. При переключении консолей синхронизируются курсоры, история вывода и рабочие директории VFS[cite: 38, 39].

## 4. Спецификация системных вызовов (`int 0x80`)

Программы пространства пользователя взаимодействуют с ядром через прерывание `int 0x80`[cite: 40]. Аргументы передаются в регистрах: `RAX` (номер вызова), `RBX` (arg1), `RCX` (arg2), `RDX` (arg3)[cite: 40].

| Номер (RAX) | Название | Параметры | Описание |
| :---: | :--- | :--- | :--- |
| `0` | `sys_exit` | `RBX = code`[cite: 40] | Завершает вызывающий процесс (переход в ZOMBIE)[cite: 34, 40] |
| `1` | `sys_print` | `RBX = str`, `RCX = color`[cite: 40] | Выводит строку на экран активного TTY[cite: 40] |
| `2` | `sys_put_pixel` | `RBX = x`, `RCX = y`, `RDX = color`[cite: 40] | Отрисовывает точку в буфер экрана[cite: 40] |
| `3` | `sys_flush` | — | Сбрасывает внеэкранный буфер в видеопамять LFB[cite: 40] |
| `4` | `sys_sleep` | `RBX = ms`[cite: 40] | Приостанавливает выполнение процесса на миллисекунды[cite: 40] |
| `5` | `sys_clear` | `RBX = color`[cite: 40] | Очищает экран указанным цветом[cite: 40] |
| `6` | `sys_get_key` | — | Считывает скан-код из кольцевого буфера клавиатуры[cite: 40] |
| `7` | `sys_get_mouse` | `RBX = out_state*`[cite: 40] | Возвращает координаты мыши и статус кнопок[cite: 40] |
| `10` | `sys_open` | `RBX = filename`[cite: 40] | Открывает файл в файловой системе[cite: 40] |
| `11` | `sys_read` | `RBX = fd`, `RCX = buf`, `RDX = count`[cite: 40] | Читает данные из открытого файла[cite: 40] |
| `12` | `sys_close` | `RBX = fd`[cite: 40] | Закрывает файл[cite: 40] |
| `13` | `sys_write` | `RBX = filename`, `RCX = buf`, `RDX = count`[cite: 40] | Записывает данные в файл на накопителе[cite: 40] |
| `14` | `sys_brk` | `RBX = new_brk`[cite: 40] | Изменяет размер кучи процесса (выделение памяти)[cite: 40] |
| `20` | `sys_set_palette`| `RBX = palette_ptr`[cite: 40] | Загружает 256-цветную палитру (для DOOM/VGA игр)[cite: 40] |
| `21` | `sys_blit_frame` | `RBX = fb_320x200`[cite: 40] | Программный скейлер кадра 320x200 в разрешение экрана[cite: 40] |
| `22` | `sys_get_tsc` | — | Возвращает аппаратную частоту TSC (тактов в 1 мс)[cite: 40] |
| `30` | `sys_fork` | — | Клонирует текущий процесс[cite: 40] |
| `31` | `sys_execve` | `RBX = filename`, `RCX = args`[cite: 40] | Заменяет тело процесса новым исполняемым файлом[cite: 40] |
| `32` | `sys_waitpid` | `RBX = pid`, `RCX = int* status`[cite: 40] | Ожидает завершения дочернего процесса[cite: 40] |
| `33` | `sys_kill` | `RBX = pid`, `RCX = signal`[cite: 40] | Отправляет сигнал процессу (`SIGINT`, `SIGKILL`)[cite: 35, 40] |

## 5. Встроенная IDE и компилятор (`redactor.sys`)

В систему встроен собственный текстовый редактор и однопроходный компилятор языка Си (`compiler.c` + `editor.c`), запускаемый как модуль ядра нулевого кольца[cite: 53, 55, 56]:

* **Интерфейс:** Многовкладочный TUI в стиле темной темы VS Code с подсветкой синтаксиса Си (ключевые слова, типы, строки, числа, комментарии)[cite: 56].
* **Препроцессор:** Обработка `#include` (чтение файлов из соседних вкладок или папки `/Code/`) и констант `#define`[cite: 55].
* **Парсер и кодогенератор:** Рекурсивный спуск выражений, генерация 64-битного машинного кода x86_64, стековых фреймов функций (System V ABI) и локальных переменных[cite: 55].
* **Три цели компиляции:**
  1. `F5` — **JIT-выполнение:** компиляция в буфер ОЗУ ядра и прямой запуск под защитой `g_jit_guard` (Ring 0)[cite: 55, 56].
  2. `F8` — **Сборка приложения `.PRG`:** компиляция с трансляцией вызовов в сисколлы `int 0x80`, пулом строк и базовым адресом `0x4000000000` (Ring 3)[cite: 33, 55, 56].
  3. `F9` — **Сборка модуля `.SYS`:** сборка перемещаемого драйвера ядра с таблицей релокаций SREL (Ring 0)[cite: 36, 56, 71].

## 6. Структура репозитория

```text
├── build/                 # Директория временных файлов и сборки образа
├── tools/                 # Скрипты упаковки бинарников (elf2sys.py, elf2prg.py)
├── linker.ld              # Скрипт линковщика Higher-Half ядра (база 0xFFFFFFFF80000000)
├── user.ld                # Скрипт линковщика Ring 3 программ (база 0x4000000000)
├── Makefile               # Главный Makefile проекта
└── src/
    ├── asm/               # Ассемблерные переходы (crt0, interrupts, switch, smp)
    ├── boot/              # Загрузчик (stage1 MBR, stage2 Unreal FAT32, vbe_menu, entry)
    ├── drivers/           # Драйверы (PCI, Display PWM, ACPI) и заголовочные API
    │   └── usb/           # Стек USB 2.0 (EHCI контроллер и Mass Storage BOT)
    ├── files/             # Вкомпилированные спрайты, шрифты и порты DOOM / Quake
    ├── font/              # Растровый моноширинный шрифт CP866 (8x16)
    ├── fs/                # Файловые системы (FAT16, FAT32 LFN, фасад VFS)
    ├── kernel/            # Ядро (main, scheduler, user_mode, TTY, BSOD, ввод)
    ├── memory/            # Менеджеры памяти (PMM bitmap, VMM 4-level paging)
    ├── modules/           # Исходный код модулей Ring 0 (.sys: cpu, gpu, clock, stress)
    └── programs/          # Исходный код программ Ring 3 (.prg: fork, math, psx, pkill)
```

## 7. Сборка и запуск

### 7.1. Необходимые зависимости

```bash
# Arch Linux / CachyOS
sudo pacman -S base-devel gcc nasm mtools dosfstools qemu-system-x86 python

# Ubuntu / Debian
sudo apt install build-essential gcc nasm mtools dosfstools qemu-system-x86 python3
```

### 7.2. Сборка образа диска

Компиляция ядра, пользовательских программ, сборка файловой системы FAT32 и финального RAW-образа диска `build/os.img`[cite: 84]:

```bash
make all
```

### 7.3. Запуск в эмуляторе QEMU

Запуск эмулятора с пробросом EHCI USB 2.0 контроллера и стандартного VGA-адаптера[cite: 84]:

```bash
make run
```

### 7.4. Прошивка на физическую USB-флешку

Makefile выполняет автоматический поиск съемного USB-накопителя и поблочную запись[cite: 84]:

```bash
# Автоматический поиск съемной флешки и запись:
make install

# Либо указание конкретного диска вручную:
make install DEV=/dev/sdX
```

После записи подключите флешку к ПК/ноутбуку и выберите ее в меню загрузки BIOS (режим Legacy / CSM Boot).
