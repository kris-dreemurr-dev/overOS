# Как написать приложение для overDesktop

Здесь лежат программы графической оболочки: проводник, блокнот, просмотрщик,
проигрыватель, терминал, диспетчер задач, параметры системы и сам композитор
(`Desktop/`). Этот файл — инструкция, как сделать такую же свою.

## 1. Что такое приложение рабочего стола

Это обычная программа Ring 3 (формат `.prg`), которая не рисует в экран
напрямую, а разговаривает с композитором `desktop.prg` по оконному протоколу
(`src/libs/common/wproto.h`, по духу Wayland):

1. программа создаёт буфер кадра в разделяемой памяти `w*h*4` и отдаёт его
   композитору (`WP_CREATE`);
2. рисует в этот буфер что хочет и говорит «кадр готов» (`WP_COMMIT`);
3. ждёт `WP_FRAME_DONE` — композитор вывел кадр, можно рисовать следующий;
4. получает события: мышь, клавиши (вместе с готовым текстом UTF-8), колесо,
   фокус, «закрой окно», «измени размер».

Руками это писать не нужно: всё закрыто тулкитом **libui**
(`src/libs/libui/ui.h`). Приложение пишет «кнопка здесь, список тут», а
протокол, буферы и события — забота тулкита.

## 2. Самое маленькое приложение

```c
#include "common/ovos.h"        // системные вызовы
#include "libui/ui.h"           // тулкит
#include "libui/libui_ll.h"     // тулкит берётся из /lib/libui.ll в runtime

// Значок окна 16x16: по биту на пиксель, 1 — закрашено
static const uint16_t icon[16] = {
    0x0000, 0x7FFE, 0x4002, 0x4002, 0x4002, 0x4002, 0x4002, 0x4002,
    0x4002, 0x4002, 0x4002, 0x4002, 0x4002, 0x7FFE, 0x0000, 0x0000
};

int main(void) {
    if (libui_bind() < 0) ov_exit(1);     // подключить /lib/libui.ll
    ui_app_id("myapp");                   // класс программы (для дока и «одного экземпляра»)

    ui_win_t* w = ui_open("Моя программа", 420, 300, icon, WP_FLAG_RESIZABLE);
    if (!w) ov_exit(1);                   // композитор не запущен

    int count = 0;
    while (ui_begin(w, UI_WAIT)) {        // ждёт событие; 0 — окно закрыли
        ui_clear(w);
        ui_label(w, 20, 20, "Привет из overOS");
        if (ui_button(w, 20, 60, 160, 28, "Нажми меня")) count++;
        char num[16];
        ui_itoa(count, num);
        ui_label(w, 20, 100, num);
        ui_end(w);                        // кадр готов
    }

    ui_close(w);
    ov_exit(0);
    return 0;
}
```

Это полноценное окно: его можно двигать, сворачивать, разворачивать, тянуть за
края, оно есть в панели задач и в меню «Пуск».

## 3. Сборка

Рядом с исходником — четыре строки makefile:

```make
TARGET   := myapp.prg
SRCS     := myapp.c
USE_LIBUI := 1                 # тулкит из /lib/libui.ll, а не линковкой внутрь
LDSCRIPT := myapp.ld
include ../../../libs/common/app.mk
```

`myapp.ld` — копия любого соседнего (все одинаковые: база `0x4000000000`).
Общая часть сборки лежит в `src/libs/common/app.mk`: он сам соберёт `crt0`,
подставит пути к заголовкам и упакует ELF в `.prg` с флагом `--desktop`.

Чтобы программа попала в образ, в корневом `Makefile` нужно:

* объявить пути рядом с остальными (`MYAPP_DIR`, `MYAPP_PRG`);
* добавить правило `$(MYAPP_PRG): FORCE` с `$(MAKE) -C $(MYAPP_DIR)`;
* добавить `$(MYAPP_PRG)` в зависимости `$(PART_IMG)`;
* скопировать в раздел: `mcopy -i $@ $(MYAPP_PRG) ::desprogs/myapp.prg`.

Всё, что лежит в `/desprogs`, само появляется в меню «Пуск».

### Программа на C++

`.cpp` ставится в `SRCS` так же, как `.c`, — `app.mk` соберёт его `g++`
(C++17) и сам подложит рантайм из `src/libs/cxxrt`.

Что надо знать:

* **Стандартной библиотеки нет**: ни STL, ни `<string>`, ни исключений
  (`-fno-exceptions`), ни RTTI (`-fno-rtti`). Есть классы, шаблоны,
  перегрузка операторов, `new`/`delete`, `constexpr`, лямбды — то, что
  делает сам компилятор.
* В `main` первым делом: `libui_bind();` и `ovcxx_init();` — второе вызывает
  конструкторы глобальных объектов.
* В скрипте компоновки нужна секция `.init_array` с метками
  `__init_array_start`/`__init_array_end` (скопируй `overCraft/overcraft.ld`),
  иначе глобальные объекты останутся несконструированными — молча.
* Куча — `new`/`delete` на `brk`. Не загружай в такую программу `libc.ll`:
  граница `brk` у процесса одна, две кучи на ней испортят друг друга.
  Нехватка памяти в `new` завершает программу с кодом 12.
* Для анимации — `ui_begin(w, 0)`: темп в 60 кадров задаёт композитор,
  спать самому не нужно. `ui_pixels(w)` меняется каждый кадр (двойной
  буфер) — бери его заново в каждом кадре.
* Если окно каждый кадр закрашивает целиком (игра, видео), позови один раз
  `ui_redraw_all(w)`: тогда `ui_end` не копирует показанный кадр во вторую
  половину буфера — на окне во весь экран это мегабайты на каждый кадр.
* Когда картинка стоит (пауза), жди с `UI_WAIT`, а не рисуй тот же кадр
  60 раз в секунду: так программа в простое не ест процессор.
* Игре от первого лица нужен захват мыши: `ui_grab(w, 1)` прячет курсор,
  дальше `ui_motion(w, &dx, &dy)` даёт смещения за кадр без упора в край
  экрана, `ui_buttons(w)` — все три кнопки. Meta или переход в другое окно
  снимают захват сами — проверяй `ui_grabbed(w)`. Зажатые клавиши — по
  `ui_raw_keys` (отпускание приходит как код | 0x80).
* Программа из нескольких `.cpp` может звать `ui_*` из любого файла:
  таблица libui одна на всю программу, `libui_bind()` достаточно в `main`.

### Вычисления на всех ядрах

Ядро ОС работает на одном ядре процессора, остальные отдаются программам как
вычислители. `ov_worker_start(fn, arg, stack_top)` запускает функцию на
свободном ядре в памяти программы; ждать и будить — `ov_wait_u32` и
`ov_wake` (всё в `ovos.h`, раздел «Рабочие ядра»). Сколько ядер свободно —
`ov_smp_info`. Пример целиком — `src/programs/smptest.c`.

Главное правило: **на рабочем ядре — только счёт**. Память, файлы, окна, `new`
— с основного потока, заранее; из системных вызовов рабочему доступны лишь
ожидание, свой номер и выход. Упавший рабочий снимает свою программу, но не
систему. Готовый пул задач поверх этого — в движке overCraft (`oe_parallel`).

### Программа-папка: своя библиотека и ресурсы

Программа может жить не одним файлом, а папкой `/desprogs/<Имя>/` — как
`.app` в macOS. Меню находит `.prg` внутри такой папки само. Рядом с ним
лежит всё, что принадлежит программе: её `.ll` и `resources/`. Путь к своей
папке программа узнаёт из пути своего исполняемого файла (`ov_proc_exe`).
Пример — overCraft (`src/files/progs/overCraft`):

```text
overCraft/                    в образе: /desprogs/overCraft/
├── makefile                  собирает и ovcraft.prg, и ovengine.ll
├── config.h                  все настройки игры: мир, игрок, камера
├── blocks.h                  виды блоков, текстуры, прочность, что выпадает
├── items.h                   предметы (номера от 64; ниже — блоки), еда
├── entities.h                мобы: модель, развёртка, хитбокс, здоровье, добыча
├── main.cpp                  связывает модули: окно, ввод, шаг игры, кадр
├── world/                    мир: шум, генератор, сетки чанков, сам мир
├── game/                     игрок и выживание, физика, мобы, модели .mdl,
│                             инвентарь, значки, рука от первого лица, интерфейс
├── engine/                   движок -> ovengine.ll
│   ├── ovengine.h            общие типы (Vertex, Mesh, Camera, FrameStats) и oe_*
│   ├── ovengine_ll.h         для игры: oe_bind, oe_game_dir, ov::Renderer
│   ├── math3d.h              Vec2/3/4, Mat4, свои sin/sqrt (общий для обеих сторон)
│   ├── jobs.h/.cpp           пул потоков на рабочих ядрах
│   ├── api.cpp               экспорт oe_* и загрузка PNG
│   └── renderer.h/.cpp       многопоточный программный растеризатор
└── resources/                картинки (tools/ovcraft_textures.py)
    ├── *.png                 текстуры блоков 16x16
    ├── items/, destroy/      значки предметов, трещины
    ├── entities/             развёртки мобов и игрока (раскладка Minecraft)
    └── models/*.mdl          модели текстом: части, точки вращения, коробки
```

```make
TARGET      := ovcraft.prg
SRCS        := main.cpp world/generator.cpp world/mesher.cpp world/world.cpp \
               game/player.cpp game/physics.cpp game/hud.cpp game/icons.cpp \
               game/inventory.cpp game/model.cpp game/shapes.cpp game/entity.cpp game/hand.cpp
USE_LIBUI   := 1
LDSCRIPT    := overcraft.ld
LL_TARGET   := ovengine.ll                         # своя библиотека
LL_SRCS     := engine/api.cpp engine/renderer.cpp engine/jobs.cpp
LL_ARENA_KB := 28672                               # куча библиотеки
include ../../../libs/common/app.mk
```

Правила для своей `.ll` — те же, что у системных (`src/libs/readme.md`):
импорта нет, наружу — функции с привязкой C (`extern "C"`), потому что
таблица символов ищет по имени, а имена C++ искажены. Глобальных объектов с
конструкторами в `.ll` быть не должно (`app.mk` проверяет). Куча у неё своя —
статическая арена: `brk` принадлежит программе. В корневом `Makefile` такую
программу копируют папкой (см. правило для `OVCRAFT_*`).

## 4. Что уметь, чтобы выглядеть своим

**Значок, имя и класс живут в самой программе.** Положите `icon.svg` рядом с
makefile и задайте две строки перед `include`:

```make
APP_NAME := Мой редактор     # имя в меню «Пуск», на панели и в уведомлениях
APP_ID   := myapp            # класс программы, тот же, что в ui_app_id()
```

`tools/elf2prg.py` вошьёт их в `.prg` ресурсами `ICON`/`NAME`/`APPI` (как
ресурсы `.exe` в Windows). Отсюда их берут все: шапка окна, панель задач,
меню, уведомления и overFiles, который рисует этот значок на самом файле
программы. Таблиц «класс → значок» в композиторе больше нет: переложили
`.prg` в другую папку — значок поехал вместе с ним. Прочитать ресурс самому —
`prg_resource(path, "ICON", buf, size)` из `common/prgres.h`; нарисовать любой
значок — `ui_icon(w, x, y, size, name, tint)`, где `name` — системный значок
из `/sys/icons` (`"drive-removable"`) или путь к `.prg`. Монохромная иконка
16x16 в `WP_CREATE` осталась запасной: её видно, только если у программы нет
`icon.svg`. В `src/files/icons/` теперь только значки темы (звук, сеть,
флешка, предупреждение) — то, что не принадлежит ни одной программе.

**Уведомления.** `#include "ovnotify.h"`, потом
`ov_notify(1, "Готово", "Видео сохранено", "")` — окно для этого не нужно,
так же работает и консольная программа (см. `src/programs/notify.c`, команда
`notify` в оболочке). id выбираете вы: тот же id заменяет прежнее уведомление,
`ov_notify_close(id)` убирает его. Кнопки: `ov_notify_ex(id, urgency, timeout_s,
icon, title, body, "Открыть", "Отмена")`, а какую нажали, скажет
`ui_notify_action(w, &id)` (0/1 — кнопка, -1 — щелчок по уведомлению, -2 —
ничего). Шапку — значок и имя программы — композитор берёт из вашего `.prg`,
а не из сообщения, поэтому подписаться чужим именем не выйдет.

**Изменение размера.** Флаг `WP_FLAG_RESIZABLE` в `ui_open` включает кнопку
«развернуть» и растягивание за край. Раскладку нужно считать от текущего
размера **каждый кадр**: `ui_width(w)`, `ui_height(w)`. Буфер кадра
принадлежит программе, поэтому композитор не меняет размер сам: он просит
(`WP_EV_RESIZE`), а новый буфер выделяет libui — от программы требуется только
не держать раскладку в константах.

**Курсор.** Над текстовым полем тулкит сам просит двутавр. Если программа
занята долгой работой, скажи `ui_cursor(w, WP_CUR_BUSY)`; формы перечислены в
`wproto.h` (`WP_CUR_*`). Края окна рисует композитор, их трогать не нужно.

**Один экземпляр.** `ui_app_id("myapp")` до `ui_open` задаёт класс программы.
Если другая программа (например, проводник) хочет открыть файл именно вашей
программой, она зовёт `ui_hand_over("myapp", path)`; composer найдёт живое окно
этого класса, поднимет его и пришлёт путь. Вы читаете его каждый кадр:

```c
const char* req = ui_open_request(w);
if (req[0]) open_file(req);
```

**Контекстное меню композитора.** Флаг `WP_FLAG_FILE_BROWSER` добавляет в меню
по правой кнопке «создать файл/папку»; команда приходит как `ui_command(w)`
(`WP_CMD_*`).

**Текст.** Шрифт интерфейса пропорциональный, поэтому никогда не считайте
ширину как «число символов × 8». Ширину даёт `ui_text_width()`. Где колонки
должны стоять друг под другом (таблицы, редактор кода), есть моноширинный
вывод `ui_text_mono()` — но помните, что русская буква в UTF-8 занимает два
байта, а на экране один знак: выравнивать надо по символам, а не по байтам.

## 5. Что можно у системы попросить

Всё — через `src/libs/common/ovos.h`, одним заголовком:

| Нужно | Вызов |
| :--- | :--- |
| файлы | `ov_open`/`ov_read`/`ov_write`/`ov_lseek`/`ov_listdir`/`ov_mkdir` |
| процессы | `ov_ps`, `ov_kill`, `ov_spawn`, `ov_getpid` |
| пользователи | `ov_getuid`, `ov_getpwuid`, `ov_is_admin`, `ov_sudo` |
| время | `ov_rtc`, `ov_ms` |
| звук и видео | `/lib/ffmpeg.ll` через `ffmpeg/av.h` + `ffmpeg/ffmpeg_ll.h` |
| картинки | `/lib/libgfx.ll` через `libgfx/libgfx_ll.h` (PNG, BMP, .ttf, .svg) |
| флешки | `ov_mounts` (что подключено в `/media`), `ov_eject` (безопасно извлечь) |
| уведомления | `ov_notify`/`ov_notify_ex` из `common/ovnotify.h` |
| математика | `/lib/libm.ll` через `libm/libm_ll.h` |

Библиотеки подключаются в runtime: `av_bind()`, `libgfx_bind()`, `libm_load()`
в начале `main`, и дальше вызовы выглядят обычными функциями. Подробности —
`src/libs/readme.md`.

Важное: **libc в программе нет**. Структуры копируются поэлементно (обычное
`a = b` для большой структуры компилятор превращает в `memcpy`, которого нет),
большие массивы объявляются `static` (стек программы — 512 КБ), а строки
собираются своими короткими функциями или `ui_itoa`.

## 6. Чего пока нельзя

* Нет каналов (`pipe`): перехватить вывод чужой программы по-прежнему нельзя.
  Для терминала это обошли иначе — см. раздел 7.
* Нет меню в заголовке окна, перетаскивания файлов между окнами и буфера обмена
  между программами.
* Окно одно на программу: диалоги рисуются внутри своего окна (см. диалог
  пароля в «Параметрах системы»).

## 7. Псевдотерминал: как устроен «Терминал»

Программе, которой нужна настоящая оболочка, каналы не требуются. Ядро умеет
выдать ей **псевдотерминал** — обычный TTY системы, такой же как tty1..tty6,
только его картинка никогда не попадает на экран. Внутри работает всё тот же
`/sys/sh.prg`, то есть все команды, включая `fastfetch`, `ps`, `su` и запуск
программ.

```c
int pty = ov_pty_open(text_w, text_h);      // размер в точках, кратен 8x16
...
int sc[32];
int n = ui_raw_keys(w, sc, 32);             // и нажатия, и отпускания
for (int i = 0; i < n; i++)
    if (!(sc[i] & 0x100))                   // 0xE0-клавиши TTY не ждёт
        ov_pty_key(pty, (unsigned char)(sc[i] & 0xFF));

if (!ov_pty_alive(pty)) break;              // оболочка завершилась

static uint32_t screen[1600 * 1000];
if (ov_pty_read(pty, screen, sizeof(screen)) > 0)
    ui_blit(w, 6, 4, text_w, text_h, screen, text_w);
...
ov_pty_close(pty);
```

Раскладку, Shift, Caps Lock, Backspace и эхо делает драйвер TTY — ровно так же,
как в текстовой консоли. Размер консоли задаётся при открытии и не меняется,
поэтому при изменении размера окна псевдотерминал открывают заново
(`src/files/progs/overTerm/overterm.c` — весь эмулятор занимает сотню строк).
Псевдотерминалов всего четыре (`MAX_PTYS`), и каждый принадлежит открывшему его
процессу: чужой не прочитать и не закрыть.
